How the CMDB upload works

  1. Herald reads the file and shows a preview: new servers, changed servers, and rows it can't use. Nothing changes yet.
  2. Apply saves the changes. Servers missing from the file are left as they are, so a partial file is safe.

A server is identified by its name, ignoring capitals. It belongs to the App ID in u_id, and CMDB always wins: a server with a u_id can't be reassigned by hand. App IDs new to Herald are added to Applications, ready for their contacts.

When applied, servers first found in a scan are linked to the CMDB server their name now matches, and their vulnerabilities move with them.
